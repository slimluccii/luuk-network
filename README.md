# luuk.network

Personal website for [luuk.network](https://luuk.network), built as a static
site with [Astro](https://astro.build). All content, including translations and
icons, comes from [DatoCMS](https://www.datocms.com).

## Requirements

- Node.js 24 and npm 11.18 or newer
- A read-only DatoCMS API token

## Getting started

```sh
npm install
```

Put the DatoCMS token in `.env` as `DATOCMS_TOKEN`. Both the dev server and the
build need it, because the site configuration, translations, icons and GraphQL
types are fetched from DatoCMS on startup.

## Commands

| Command           | Action                                   |
| :---------------- | :--------------------------------------- |
| `npm run dev`     | Start the dev server at `localhost:4321` |
| `npm run build`   | Build the site to `./dist/`              |
| `npm run preview` | Preview the build locally                |
| `npm run check`   | Type-check `.ts` and `.astro` files      |
| `npm run lint`    | Lint, including type-aware rules         |
| `npm run format`  | Format everything except `.astro` files  |

## How it fits together

- **Content** is loaded into an Astro content collection by the loader in
  `src/datocms/`, which queries the DatoCMS Content Delivery API.
- **GraphQL types** are generated from the `.graphql` files into
  `.generated/datocms.ts`, and regenerated by the dev server when a `.graphql`
  file changes.
- **Integrations** in `integrations/` run when Astro starts. They read the
  locales from DatoCMS, build the icon sprite and the translations, and turn
  `src/tokens.json` into CSS custom properties.
- **Routes** are prefixed with the locale, for example `/en/...`. Page slugs
  come from DatoCMS.

## Code quality

The pre-commit hook formats staged files with Oxfmt and fixes them with
`oxlint --fix`, then restages them. Partially staged files are only checked,
so unstaged changes never end up in a commit.

## Security

- npm blocks install scripts of dependencies unless they are approved in
  `allowScripts` in `package.json`. Review a package before approving it with
  `npm install-scripts approve <pkg>`.
- `min-release-age=2` in `.npmrc` only installs package versions that are at
  least two days old, so a malicious release has time to be caught and pulled
  first.
